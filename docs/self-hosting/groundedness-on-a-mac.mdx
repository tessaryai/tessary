---
title: "Groundedness on a Mac, using the GPU"
description: "Run the groundedness classifier's model on your Mac's GPU next to a self-hosted Tessary stack: one native process, two environment variables."
---

The `groundedness` classifier scores every retrieval-shaped answer with a 395M-parameter model. In a
self-hosted stack that model runs inside the `classify` container, on CPU, because Docker on a Mac
cannot reach the GPU. On an Apple silicon Mac that costs 2 to 6 seconds per answer and cannot score
the longest ones at all. This page moves the model out of the container and onto the Mac's GPU. The
rest of the stack stays in Docker and does not change.

What you get, measured on an M4 Pro: about 0.1 seconds for a typical answer and 3.5 seconds for one
that fills the model's 8,192-token window, against 2.2 seconds and a crash in the container. The
scores are identical to the container's; only the hardware changes.

<Note>
  Apple silicon only for the GPU. On an Intel Mac the same process runs on CPU, still outside the
  container's VM, and is faster than the container but not by the margin above. On a Linux host with
  an NVIDIA GPU the same command uses CUDA.
</Note>

## What you need

- A self-hosted Tessary stack on this Mac, per [Set up Tessary](/self-hosting/setup), started from a
  clone of the repository (the process runs from the repository's `classifiers` directory).
- [uv](https://docs.astral.sh/uv/) (`brew install uv`) and the Xcode command line tools.
- 6 GB of free disk for the Python environment and the model, and 4 GB of memory while it runs.
- Network access to Hugging Face on first start, to download the public model
  (`tessaryai/groundedness-token-v1`, MIT, 1.6 GB). After that it runs offline.

## 1. Start the model service

From the repository root:

```bash
cd classifiers
uv sync --extra train
KEY="$(openssl rand -base64 24)"; echo "$KEY"
uv run --extra train python -m groundedness.serve --key "$KEY"
```

The first run installs PyTorch and downloads the model, which takes a few minutes. Every later start
takes about five seconds. The service prints what it chose and what to configure:

```
loaded tessaryai/groundedness-token-v1 on mps (fp32) in 5.4s
listening on http://127.0.0.1:18080 — set TESSARY_OBSERVER_ENCODER_URL=http://host.docker.internal:18080 and TESSARY_OBSERVER_ENCODER_API_KEY to the key
```

`mps` is the Apple GPU. It listens on localhost only; the containers reach it through Docker's
`host.docker.internal` name, and every request must carry the key.

Keep the key the `echo` printed: the backend needs the same value in step 2, and passing your own
key rather than letting the service generate one (which it does when `--key` is omitted, printing it
once) means it survives restarts unchanged.

## 2. Point the backend at it

Add two lines to the `.env` beside your `docker-compose.yml`, then recreate the backend:

```bash
TESSARY_OBSERVER_ENCODER_URL=http://host.docker.internal:18080
TESSARY_OBSERVER_ENCODER_API_KEY=<the key from step 1>
```

```bash
docker compose up -d backend
```

Do not also start the `classify` profile. The backend uses whichever encoder the URL names, and
running both would only spend memory.

## 3. Confirm it is scoring

Ask the service directly, with an answer that contradicts its evidence:

```bash
curl -s -X POST http://127.0.0.1:18080/classify \
  -H "Authorization: Bearer <the key>" -H 'Content-Type: application/json' \
  -d '{"head":"groundedness","responses":[{"passages":["Refunds take 5 business days."],
       "question":"How long do refunds take?","answer":"The refund is paid within 2 hours of collection."}]}'
```

A working service answers with `"unsupported"` close to 1.0 and the flagged span. Then check the
stack's side: the groundedness classifier is enabled by default on every project, so once traces
whose call site declares a retrieval shape (`rag_answer`, `summarize`, `extract`) and carry retrieved
documents are flowing, findings appear under **Classifiers** without any further setting. Three
unsupported answers in a day open a finding; a confirmed finding opens a case, per
[Cases](/concepts/cases).

If nothing appears, the backend log says why on every sweep tick: an unreachable encoder shows as a
connection error against `host.docker.internal:18080`, a wrong key as a 401.

## 4. Keep it running

The service is a plain process, so it stops when the terminal closes. To run it at login, save this
as `~/Library/LaunchAgents/ai.tessary.groundedness.plist`, with your paths and key filled in:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>ai.tessary.groundedness</string>
  <key>ProgramArguments</key><array>
    <string>/opt/homebrew/bin/uv</string><string>run</string><string>--extra</string><string>train</string>
    <string>python</string><string>-m</string><string>groundedness.serve</string>
    <string>--key</string><string>YOUR_KEY</string>
  </array>
  <key>WorkingDirectory</key><string>/path/to/tessary/classifiers</string>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>/tmp/tessary-groundedness.log</string>
  <key>StandardErrorPath</key><string>/tmp/tessary-groundedness.log</string>
</dict></plist>
```

```bash
launchctl load ~/Library/LaunchAgents/ai.tessary.groundedness.plist
launchctl list | grep tessary
```

`launchctl unload` the same file to stop it. The log carries one line per scored batch with the
time it took.

## Options

| Flag | Default | When to change it |
| --- | --- | --- |
| `--device` | `auto` (Metal, then CUDA, then CPU) | Force `cpu` to compare, or when a Mac's GPU is needed for something else. |
| `--dtype` | `fp32` | `fp16` is 20 to 30 percent faster and halves memory, and moves scores by up to 0.03. Use it on a 16 GB Mac; expect a few borderline answers to change band. |
| `--port` | `18080` | Any free port; change the URL in `.env` to match. |
| `--model` | `tessaryai/groundedness-token-v1` at the pinned revision | A local checkpoint directory, for a model you trained yourself. |

## Where it does not help

- **Answers under 1k tokens are already quick on CPU** once the container has enough cores. The
  GPU matters when your evidence is long: above 4k tokens it is the difference between seconds and
  half a minute, and above 8k the container cannot score the answer at all.
- **The `frustration` classifier** is not served by this process: it runs on your own provider key.
  See [Watch for frustrated users](/classifiers/frustration).
- **Several Macs** cannot share one service without exposing it beyond localhost. Put the stack and
  the service on the same machine, or run the model service on a Linux GPU host and set the URL to
  it over your own network.
