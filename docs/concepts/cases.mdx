A case is a validated issue that requires attention. It is the one shape in Tessary that is meant to reach a person, and it exists only after triage has ruled that the finding behind it represents a real issue, or, for a high-confidence secret leak or a frustration finding, once the classifier has filed it already ruled.

Findings are cheap and plentiful by design, because the classifiers that produce them are built to run against every trace. Putting every finding in front of someone would undo that. Triage is the gate that makes watching everything affordable to read.

## What triage does

Triage runs an agent in a sandbox against one finding. It is given the finding's claim as a dossier, two files: what the classifier asserts, over what population, since when, and how large each evidence set is, plus the classifier's own numbers verbatim. Everything else it needs, the traces and spans and sessions the claim is about, it fetches for itself through your instance's MCP (Model Context Protocol) surface, with a short-lived project key minted for the run and revoked when it ends. It chooses its own sample rather than being handed a pre-picked exemplar, and it states what it took.

It has no repository. That is deliberate: triage rules on evidence, and reading the code is the next stage's job.

The question it answers is narrow. Does the claim hold, was it measured over enough samples, and is it carried by the evidence it cites?

**Triage never judges impact.** A cost or duration drop passes its gate exactly like a rise, because "improvement" is a judgment about intent and triage has no evidence about intent.

| Ruling | What happens |
| --- | --- |
| `positive` | The claim holds. The finding stays open, and opens or joins the case for its cause. |
| `negative` | The claim does not hold. The finding closes. |
| No ruling | The run did not settle the question, never reached the evidence, or did not happen at all. Nothing is written and the job retries. |

A ruling settles the finding it landed on for good: closed on `negative`, or open only as long as the case it backs stays unresolved. Either way, the next time the cause fires it is a fresh finding, triaged from scratch: closing on `negative` is safe because a cause that is real fires again and gets a second look, and a cause that was a one-off costs nobody a queue entry it never re-enters.

A ruling changes nothing about the classifier itself. It never moves a baseline and never resolves anything. Absorbing a shift moves the reference an entire population is judged against, and that stays a decision a person makes.

### What triage needs before it can run

- **An LLM (large language model) provider credential**, configured in-app under **Settings → Providers**. Triage jobs park on a missing credential and re-check later rather than burning their retries, so adding the key afterward lets them proceed. On Tessary Cloud, a one-time model credit pays for triage while you have no key of your own. Once it is used up, add a key to keep triage running. See [Usage and credit](/cloud/usage-and-credit).
- **A reachable `sandbox-runner` service**, which the self-hosting configuration starts by default. See [Set up Tessary](/self-hosting/setup#prerequisites) for the Docker socket group id it needs on Linux.
- **Automatic triage turned on for your organization.** Self-hosted, it is off by default, because running it unattended drives model spend with no ceiling, so it is an opt-in an operator takes knowingly. An owner or admin turns it on under **Settings → Features**. With it off, findings are still filed and still visible, and nothing escalates them on its own. On Tessary Cloud, automatic triage is not available: triage starts only when you select **Run triage** on a finding.

## How findings collapse onto one case

Three things identify a case: the classifier that noticed, the subject it fired against, and the measure. There is at most one live, unlocked case per that combination, which is what keeps a long-running problem readable.

The subject is the population, not the finding. A tool's failure rate rising in March and falling in April are two causes to explain and one thing to page about, so both land on the same case. The same holds for a call site whose latency moved twice.

A case opens the moment a finding's ruling qualifies it (a triage positive, a person's **Real deviation**, or the ruling a high-confidence secret leak or a frustration finding carries when it is filed), never on a later sweep. Every later positive on the same key **joins** the open case rather than opening a second one: the finding is linked to it, the headline (title, basis, the measured value) refreshes to that finding's own account, and the activity trail records the join. Severity only ever rises across a case's findings, and the trail records an escalation only when it has meaningfully deepened, not on every join.

A case closes only when a person closes or absorbs it. Nothing closes on silence. A cause that stops firing simply stops adding findings to its case; the case stays open, on **Triage**, until someone acts on it.

## The states a case moves through

| State | Meaning |
| --- | --- |
| `open` | Live. It is on **Triage** and it can notify. |
| `resolved` | Closed. |

A closed case records how it closed, and the difference is load-bearing:

| Resolution | What it says |
| --- | --- |
| `human` | A person pressed **Close**. The evidence in the case's findings is left out when the baseline is set, so an unchanged population opens another case. |
| `absorbed` | A person pressed **Absorb**. The evidence in the case's findings counts toward the baseline, so this level is the new normal and does not open another case. |

Both close every finding the case still holds open, in the same action. Use **Close** when you fixed the cause or it was not a real problem. Use **Absorb** when the new level is correct and you want it to become normal.

**Close** and **Absorb** sit on the **Why** line of the case page, beside the RCA (root-cause analysis) response, so they appear only once RCA has produced a report. Each asks you to confirm. A secret leak, malformed output, or frustration case can only be closed.

### Closing a frustration case

A frustration case skips triage. The classifier rules its own finding positive and opens the case when a call site's rate of frustrated sessions rises above the rate it learned, because the numbers on the finding are the claim.

Closing one restarts that call site's test: the accumulator goes back to zero, and the call site learns its normal rate again from the sessions after the close. The sessions the case cites still count as frustrated. The rate is re-learned from whatever comes next, so close the case once the fix is live. Closed before it lands, the call site learns the frustrated rate as its normal and is flagged only if it gets worse than that.

### Closing a groundedness case

A groundedness case comes through triage like most cases. Its finding says a call site's share of traces with a flagged answer rose above the share it learned as normal.

Closing it restarts the call site's test the same way: the accumulator goes back to zero, and the call site learns its normal share again from the traces after the close. **Absorb** restarts the test too, because a groundedness call site has no reference to pin, only one it learns. What differs is the record: an absorbed case says the new level is correct. Either way, the answers the case cites stay flagged.

Every state change writes a line to the case's activity trail in the same transaction, so a case with no trail entry cannot exist. The trail records opening, a later finding joining, escalation, RCA requests and completions, closing, and absorption. Cases that were muted before Mute was removed went back to open, with a trail line that says so.

## Running RCA locks the case

Pressing **Run RCA** locks the case, at the moment of the press: no later finding can join a locked case, so the case an agent is reading stays exactly what the person saw when they pressed the button. The cause's next positive opens a **new** case instead of joining the locked one. Re-pressing on an already-locked case coalesces onto the same report, exactly as before locking existed. It only ever analyzes one finding, the one the case held when it was first pressed.

A locked case is otherwise ordinary: it can still be closed or absorbed, and a person can still read it and its report at any time.

## Where a case reaches you

New cases are listed on **Triage**, which is also where a project reports its progress when its queue is empty. Tessary does not send notifications yet, so check **Triage** to see new cases.
