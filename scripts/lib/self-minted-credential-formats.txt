# Every credential format this product itself MINTS or ACCEPTS (epic 6 clause 1, #1146), and the
# gitleaks rule in scripts/lib/gitleaks-self-minted.toml that catches each one. A scanner with no
# rule for a format we mint goes green on it forever; this file is the enumeration that rule set
# is diffed against, and `check-scrub.sh --prove-rules` plants one synthetic instance of every
# `rule` row below and requires the gate to flag it.
#
# Row shape:   <format>|<rule id or NONE>|<shape>|<minted or accepted where>|<why this rule, or why none>
format|rule|shape|where|note
API key, all three scopes|tessary-api-key|tsy_ then w, q or a, then _ then 22 url-safe base64 chars (16 random bytes)|backend/tenancy ApiKeyService; also the MCP personal token and the plugin device-link mint|the only long-lived bearer the product issues; write scope is the OTLP ingestion token
Device-link device code|tessary-device-code|link_ + 32 url-safe base64 chars (24 random bytes)|backend/tenancy DeviceLinkService|short-lived, but it is exchanged for an API key, so a leaked one inside its window is a key
Device-link user code|NONE|8 chars from ABCDEFGHJKMNPQRSTVWXYZ23456789, shown as XXXX-XXXX|backend/tenancy DeviceLinkService|a pairing code typed by a human, minutes-lived, single use, 30^8 space; a rule on that shape would match ordinary text everywhere and catch nothing a scanner should own
Session sealing key|tessary-sealing-key|EVALS_AUTH_COOKIE_PASSWORD or EVALS_SECRET_KEY assigned a 44-char base64 value, directly or inside a compose default|docker-compose.yml, .env, SSM|the two placeholder values docker-compose.yml ships are public by design (#1230) and allowlisted in the rule; any OTHER value next to those names is a real key
Service-to-service key|tessary-service-key|either side of each symmetric pair: CLASSIFY_API_KEY/EVALS_OBSERVER_ENCODER_API_KEY, COMPILE_SERVICE_KEY/EVALS_COMPILE_SERVICE_KEY/EVALS_SOP_COMPILE_API_KEY, SLACK_SERVICE_KEY, SANDBOX_API_KEY/EVALS_*_LAUNCHER_API_KEY, EMBED_API_KEY, assigned 32+ hex or 40+ base64 chars, directly or inside a compose default|compose fragments, the paid compose, SSM, the boot checks (openssl rand)|symmetric bearer between the backend and classify, compile, slack and the sandbox launcher; minted with openssl rand
Database password|tessary-db-password|POSTGRES_PASSWORD or EVALS_DB_PASSWORD assigned any value other than the compose placeholder `evals`|docker-compose.yml, .env, SSM|the placeholder is public by design and the port is not published; a different value is a real credential
License key|NONE|not minted yet|epic 9 (license enforcement) will mint it|epic 9's opening pass must add its format here and its rule to the toml, and re-run --prove-rules, before any key is issued
Telemetry token|NONE|none: the home.tessary.ai heartbeat carries an install id, not a credential|backend/core telemetry|nothing to catch; an install id is not a secret
Artifact or image signing key|NONE|none: release.yml signs nothing (clause 10, #1155, deferred)|—|when #1155 lands cosign, its key format joins this file
